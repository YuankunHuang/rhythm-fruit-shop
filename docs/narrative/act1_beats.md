## 五、写法

**JSON 字段：**

| 字段 | 写在哪 | 意思 |
|---|---|---|
| `backdrop` | 对话段 | 地点：`apartment`（家，早上）、`apartment_night`、`shop_front_day`、`subway_entrance_night`、`bus_interior_night`。不写就是店里 |
| `cast` | 对话段 | 这一段开始时已经在场的人 |
| `enter`、`exit` | 某一句 | 上场、下场，一个人写字符串，几个人写数组。写在描写离开的那句旁白上 |
| `phone` | 某一句 | 手机卡片：`{ "title": "…", "items": [{ "kind": "msg" \| "news" \| "note", "from": "…", "text": "…", "replies": ["…"] }] }`，这一句不写 `text` 和 `speaker` |
| `ticker` | 对话段，或某一句 | 跑马灯，字符串数组 |
| 回家 | `settle` 之后的对话段 | 玩家在工钱条上点“回家”以后播放 |

**点单：** 每一单都用 `service_select`，`allowRetry: false`，选项三个（给 `label` 和一句 `hint`），`customer` 写人名。紧跟它的 `score_branch` 要有：
- `branches`：三档，`min` 是 88、62、0；
- `byDrink`：每一款错的饮品一段，写喝到以后的反应；可以是数组，也可以按 `good`、`ok`、`bad` 分档；
- `byStyle`：从第 3 天焰子那一单起，`swipe` 一段；
- `after`：反应之后的收尾，人通常在这里走，记得 `exit`。

选单的 `onWrong` 写选错的那一刻：客人看见你拿错了杯子、或者说“我要的不是这个……算了”。写完这一刻，错的那杯照样做。

**说话人和表情**（只能用已画的）：
- 柚子：neutral、smile、teasing、deadpan、annoyed、panic、relieved、serious、sigh
- 林小末：neutral、tired、smile、awkward
- 阿晟：neutral、tired、focused
- 程晚：neutral、tired、professional_smile
- 老王：neutral、laugh、wistful
- 老方：neutral、weary、warm_smile
- 老弦：neutral、pensive、quiet_warmth
- 猫小姐：neutral、curious、smile
- 焰子：neutral、sharp_alert、grin
- 送餐机器人：说话人写“配送机器人”（第 8 天才叫小递），表情 neutral、smile、waiting、mimic
- 只出声音（不上台）：妈、爸、房东、中介、测量员、拓展专员，等等。

**防“AI 味”**：人物档案开头的八条，逐条对照。最常犯的三条：
- 每轮对话押一个笑点；
- 旁白替人物解释意思；
- 人人说一样的短句冷幽默。

**完成线（每一天）：**
- `node tools/route_check.mjs --story30` 这一天零缺口；
- 只用上面列出的说话人和表情；
- 有回家；
- 有跑马灯；
- 离开的人都有 `exit`。
