# 店铺经营与顾客故事设计 v0.2

本文档是《节奏鲜果铺》当前经营/剧情方向的主文档。旧版“一首完整曲 = 一班营业”的结构仅作为原型阶段遗留，不再作为完整设计目标。

## 1. 设计定位

《节奏鲜果铺》不是“玩家演奏音乐赚钱”的游戏，而是“玩家用节奏完成鲜果服务”的游戏。

玩家身份从暑期实习生开始，逐步被信任、升职、承担更多店铺责任。音乐是制作饮品时的节奏感和戏剧化表现，不是顾客点播的演出。

核心体验目标：

- 让每次打歌都有服务对象和经营理由。
- 让顾客故事、店铺成长和音游表现互相解释。
- 用短服务片段承载日常营业，用完整曲承载关键时刻。
- 让玩家从“临时打工”逐渐获得“这是我的店、也是我的家”的归属感。

## 2. 玩家身份成长线

1. **暑期实习生 / 临时店员**
   - 刚入职，不熟练。
   - 教学关是“培训上岗”。
   - 核心压力是付房租、保住工作、别给店添麻烦。

2. **正式店员**
   - 能独立接待普通顾客。
   - 认识常客，开始理解他们的偏好和烦恼。
   - 解锁基础菜单、基础 service segment 和少量店铺升级。

3. **值班负责人**
   - 老板不总在店里。
   - 玩家开始安排时段、处理突发事件、决定今日主推。
   - 经营系统从“执行任务”转为“做选择”。

4. **分店长**
   - 获得设备升级、菜单扩展、装修和时段开放的决策权。
   - 店铺风格开始被玩家塑造。

5. **住店店长**
   - 因为房租、剧情或个人选择搬到店里。
   - 店铺从工作地点变成生活空间。
   - 升级店铺也等于改善自己的家。

## 3. 音乐结构

### 3.1 Service Segment

`service segment` 是 30-45 秒短片段，用于日常顾客服务。它像调酒配方一样，绑定顾客需求、饮品风格、情绪和风险收益。

用途：

- 常客来访时的特殊需求。
- 半固定客群的日常订单。
- 路人订单和短经营压力。
- 对话后的即时服务反馈。

一个 segment 应包含：

- 顾客类型。
- 饮品/服务情绪。
- 时段。
- 音乐风格。
- 谱面密度。
- 经营收益和风险。

示例：

```json
{
  "id": "student_rush_orange",
  "song": "audio/service/student-rush.m4a",
  "start": 12.0,
  "duration": 36.0,
  "mood": "sweet_fast_bright",
  "customerTags": ["student", "rush"],
  "serviceTags": ["sweet", "quick", "orange"],
  "risk": "low",
  "reward": "tips"
}
```

### 3.2 Full Track

完整曲通常为 90-120 秒，用于：

- 练习模式。
- 挑战模式。
- 培训最终考核。
- 评论家、VIP、Boss 顾客。
- 夜市活动、街区节奏祭、店铺周年等剧情高潮。
- 自愿加班和高质量表现挑战。

完整曲不承担所有日常营业，否则顾客服务节奏会被拖慢。它应该是“重要时刻”和“进入工作心流”的舞台。

## 4. 核心循环

### 4.1 常客服务循环

1. 常客进店，带来近况、情绪或事件。
2. 对话给出特殊需求。
3. 玩家选择菜单、segment 或少数情况下选择完整曲。
4. 打歌完成制作。
5. 顾客反馈，关系推进。
6. 可能解锁后续剧情、菜单、clip 或特殊订单。

### 4.2 普通营业循环

1. 没有核心常客来访。
2. 系统生成半固定客群和路人订单。
3. 系统倾向推荐玩家较少打的曲目或 segment。
4. NPC 店员可以闲聊几句，补充世界观、房租压力、店铺背景或玩家成长。
5. 玩家完成若干短服务，获得金币、口碑和熟练度。

### 4.3 完整曲挑战循环

1. 玩家遇到重要事件、关键顾客、加班或主动挑战。
2. 选择完整曲。
3. 打完整谱面。
4. 根据表现触发 ZONE bonus、特殊评价、额外小费、常客对话或招牌值。

## 5. 顾客结构

顾客不应全都做成深度 NPC，也不应全都只是订单。推荐三层结构：

### 5.1 核心常客 NPC

数量建议 5-8 个。每人有：

- 3-6 次来店事件。
- 明确偏好和禁忌。
- 关系进度。
- 专属或推荐 segment。
- 至少一个关键剧情节点。

候选常客：

- **学生**：甜、快、便宜。围绕考试、社团、青春压力。
- **上班族**：提神、快速、稳定。围绕加班、职业疲惫和生活妥协。
- **夜班司机**：安静、温热、低风险。围绕孤独、夜路和城市边缘。
- **评论家**：挑剔、精准、高风险。阶段考核角色。
- **神秘老顾客**：牵引店铺过去和主线。

### 5.2 半固定客群

用于经营变化，不需要深剧情：

- 学生团。
- 上班族。
- 夜市客。
- 司机。
- 游客。
- 附近店员。

他们有稳定标签、偏好和事件表现，能让店铺像真实街区的一部分。

### 5.3 路人订单

只负责经营压力、收入和节奏变化。文案应短，不应抢常客剧情。

## 6. 每日结构

每日不固定为“几首完整曲”。更推荐按事件类型生成：

### 常客日

- 有核心 NPC 来访。
- 对话量较高。
- 使用特殊需求、专属 segment 或关键曲目。
- 推进关系和剧情。

### 普通营业日

- 没有核心常客或只有短问候。
- 以半固定客群和路人订单为主。
- 系统推荐较少打的曲目或 segment。
- NPC 店员可以用闲聊补设定。

### 休息日

- 默认可以整理店铺、练习、升级、查看关系、触发生活剧情。
- 玩家可以选择自愿加班。
- 自愿加班通常使用完整曲或长服务，收益高但有疲劳、时间或次日状态代价。

## 7. ZONE 系统

ZONE 表示玩家进入工作心流，是高 combo / 高表现触发的正向 buff。

触发条件可混合使用：

- 当前 combo 达到谱面总 note 的一定比例。
- 当前 combo 达到绝对值。
- 完整曲中达到更高阶条件。

建议分层：

- **Zone I**：小费提升，店员一句轻评价。
- **Zone II**：满意度、出品收益或结算照片提升。
- **Zone III**：触发特殊顾客反应、常客好感、招牌值或隐藏对话。

设计原则：

- ZONE 不改变判定窗口，避免破坏音游公平性。
- ZONE 主要影响经营反馈和叙事反馈。
- 短 segment 可以触发低阶 ZONE，完整曲更适合触发高阶 ZONE。

示例对话：

- 店员：“刚才那段你完全没看订单，是身体自己在动吧？”
- 常客：“这杯和平时不一样，你今天状态很好。”
- 评论家：“我本来想挑刺，但那段出餐确实漂亮。”
- 主角：“有那么十几秒，我忘了房租，也忘了手抖。”

## 8. 教学关：培训上岗

教学关应从普通教程改成带对话的“培训上岗”。

推荐结构：

1. 店长或前辈介绍玩家：新来的暑期实习生。
2. 第一杯训练单开始。
3. 点击教学：切水果。
4. 长按教学：榨汁/搅拌。
5. Combo 教学：出餐流畅。
6. 顾客轻反馈：“新人做的？还挺清爽。”
7. 结尾显示第一笔工资/小费，以及“距离本周房租还差 X”。

这能让玩家从第一分钟理解：自己不是在刷分，而是在靠节奏工作、服务客人、维持生活。

## 9. 经营资源

### 金币

来源：

- 服务收入。
- 小费。
- 加班费。
- 订单奖励。
- 每日目标奖励。

用途：

- 付房租。
- 升级设备。
- 解锁菜单。
- 修复店铺问题。
- 购买装饰。
- 改善住店生活空间。

### 口碑

来源：

- 常客好评。
- 高满意度服务。
- ZONE bonus。
- 评论家或 VIP 认可。
- 活动表现。

用途：

- 解锁更高客流。
- 解锁黄昏、夜间、深夜时段。
- 解锁特殊顾客。
- 解锁街区活动。

### 熟练度

来源：

- 处理对应水果。
- 完成对应菜单。
- 在特定 segment 中高质量完成。

用途：

- 解锁高级菜单。
- 提高相关订单价值。
- 改善结算照片和顾客评价。

### 疲劳

主要来自自愿加班和连续高强度完整曲。疲劳不应直接破坏判定公平性，但可以影响：

- 次日可选行动。
- 顾客等待压力。
- 剧情对话。
- 加班收益递减。

## 10. 订单与菜单

订单是顾客需求的玩法化表达。

基础订单：

- 鲜果杯：单点成功产出。
- 果汁：长按成功产出。
- 快速出餐：短时间内完成服务。
- 稳定出餐：限制 Miss。

进阶订单：

- 指定水果。
- 混合饮品。
- 心情安抚。
- 评论家试饮。
- 夜市限定。
- 加班长单。

菜单解锁应和剧情、常客、设备、时段绑定，而不是只用金币购买。

## 11. 结算反馈

练习模式和营业模式必须分开。

### 练习结算

只显示谱面表现：

- Rank。
- Timing。
- Perfect / Great / Good / Miss。
- Max Combo。
- Early Release。

不写入经营状态。

### 服务结算

用于 segment 或日常顾客：

- 顾客满意度。
- 小费。
- 关系变化。
- 订单完成。
- 顾客反馈文案。

### 完整曲结算

用于关键班次、加班、挑战：

- 谱面成绩。
- 经营收入。
- ZONE bonus。
- 特殊评价。
- 可能触发剧情 flag。

### 每日报告

用于一天结束：

- 今日收入。
- 房租/生活压力。
- 口碑变化。
- 常客关系变化。
- 店铺升级建议。
- 明日事件提示。

## 12. MVP 实现顺序

### Phase 1：叙事入口修正

- 教学关改为培训上岗。
- 首页和开场文案明确实习生身份、房租压力和店铺成长。
- 练习/营业结算边界清晰。

### Phase 2：顾客日结构

- 增加少量顾客卡数据。
- 实现常客日、普通营业日、休息日的基础调度。
- 普通日倾向推荐较少打的曲目或 segment。

### Phase 3：Service Segment

- 为 2-3 首曲目配置 30-45 秒 segment。
- 让 segment 可以绑定顾客、需求、时段和收益。
- 保留完整曲作为练习和关键班次。

### Phase 4：ZONE Bonus

- 基于 combo 比例和绝对值触发 Zone I/II/III。
- 只影响经营和叙事反馈，不改变判定窗口。
- 在结算和对话中体现心流状态。

### Phase 5：升级与生活空间

- 设备升级。
- 菜单解锁。
- 店铺装修。
- 住店生活空间。
- 休息日和自愿加班。

## 13. 当前试玩版下一步

最推荐的实现顺序：

1. 重写教学关为培训上岗。
2. 抽象顾客/事件数据结构。
3. 增加 `service segment` 数据结构，但先不大规模切谱。
4. 实现 1 个常客、1 个普通日、1 个休息日。
5. 给完整曲加 ZONE bonus 结算。

目标不是立刻做大量剧情，而是验证：

- 顾客需求是否能自然导向打歌。
- 30-45 秒 segment 是否比完整曲更适合日常营业。
- 完整曲是否能通过 ZONE 和剧情高潮保留价值。
- 玩家是否愿意为了常客、房租和店铺成长继续开店。
